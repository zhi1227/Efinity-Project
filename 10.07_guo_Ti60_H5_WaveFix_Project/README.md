# H5：修复招手确认与摆腕检测，HDMI 显示 8×8 图案

工程目录：`D:\FPGA\Ti60_Vision6_WaveFix`。
目标器件：Ti60F225 / Ti60_MP。原 H4 工程 `D:\FPGA\Ti60_Vision6_GestureLearn` 保留，便于回退。

本版针对“已经录入，但张开手掌左右摆动仍一直等待”的问题，增加独立的张掌特征、手指区域左右摆动检测和分步状态提示。原有的点赞、单手小爱心以及六模式菜单继续保留。

**下载后必须重新录入三个手型。** 模板和肤色不写入 Flash；这里使用个人轮廓模板及张掌规则，不是通用预训练模型。实拍视频用于定位现象，手机拍摄的显示器画面不能替代摄像头原始像素来测准确率。

## 下载哪个文件

- 临时运行：Programmer 的 **JTAG** 模式选择本目录 `outflow\Ti60_Demo.bit`（交付副本名 `Ti60_H5_WaveFix.bit`）。
- 保存至配置 Flash：**SPI Active** 模式选择 `outflow\Ti60_Demo.hex`（交付副本名 `Ti60_H5_WaveFix.hex`）。
- 不要把 `.bit` 用于 SPI Active，也不要用旧文件冒充本版。正确画面底部有 **H5**，右下方有“手部轮廓预览”，未录入时显示“请先录入”。
- 下载器的器件应与 Ti60F225 一致；本包附编译报告与 SHA-256 校验值。此工程未由助手下载至实物板。

## 第一次操作：只用 K1、K2

1. **K1** 切到第 6 模式“手势互动”，确认摄像头画面会动。
2. **长按 K2 约 2 秒后松开**，进入“录入手掌”。长按只进入录入，不会同时执行短按冻结。如果之前冻结，会请求恢复实时画面。
3. **录入手掌**：张开手掌，手指朝上并分开，把**掌心盖住画面中粉色小方框**。整个手和所有指尖放进大框，尽量只让一只手出现在大框内。
4. 短按并松开 **K2**。绿色条倒计时约 2 秒，随后采集掌心肤色和手型；保持不动，直到屏幕变成“录入点赞”。
5. **录入点赞**：拇指向上，其余四指握紧，确认右下黑白预览能看见突出的拇指。短按 K2，倒计时后保持不动，等待“录入比心”。此时不再要求掌心盖住小框。
6. **录入比心**：用**单手拇指、食指交叉的小爱心**，其余手指收起；尽量正对摄像头，让顶部两指的形状与点赞明显不同。短按 K2，倒计时后保持不动。
7. 三种录入完成后，按下面的状态提示使用：
   - **WAVE**：先张开手指，等提示“手掌已确认：左右摆手”；再左右摆动并回摆，可以移动整只手，也可以摆动手腕。看到“向反方向摆”时回摆，识别后显示 WAVE 的 8×8 图案。静止张掌不会触发。
   - **THUMB UP**：按录入时的朝向竖起拇指，保持片刻。
   - **HEART**：做录入时的单手小爱心，保持片刻。

录入结束后，**K2 短按仍是冻结/恢复**；识别在冻结期间停止。**K1 仍切换模式**，录入途中按 K1 可以退出。**长按 K2 会清除本次样本并从手掌重新录入**。

模板和肤色保存在 FPGA 的运行状态中：切换模式、冻结/恢复会保留，**重新上电、重新下载或复位后需重新录入**。不需要串口助手，不需要触摸屏。

## 看懂提示，避免反复盲调

| 提示或画面 | 含义 | 怎么处理 |
|---|---|---|
| 请先录入 | 三种样本尚未齐全 | 模式 6 长按 K2 进入录入 |
| 肤色失败：掌心对准小框 | 小方框采到背景、过曝或颜色不合适 | 掌心完全盖住粉色小框，调整灯光，再短按 K2 |
| 手型太相似：调整重录 | 当前录入轮廓和另一类太接近 | 点赞握紧四指；比心转动少量角度，让交叉两指可见，再短按 K2 |
| 轮廓不稳：检查预览重录 | 没有连续取得完整、稳定的手型 | 看右下预览，检查距离、背景、手指是否越框，再短按 K2 |
| 预览为棕色块 | 当前没有可用于分类的稳定候选 | 把完整手移回大框、简化背景；不表示已经识别成功 |
| 预览只剩掌心/部分手指 | 肤色分割或候选框仍不完整 | 调整照明与角度，避免背光；重新录入掌心肤色 |
| 预览大部分全白 | 手和衣服/背景粘连，或只截到一小块皮肤 | 换到与肤色差别明显的背景，让手离开脸和前臂的大面积皮肤 |
| 手部丢失：回到大框内 | 本帧没有可用的手部候选 | 将完整手和指尖放入框内，先停稳 |
| 未确认张开手掌，请分开手指 | 有候选，但张掌证据不足 | 张开并分开手指，正对摄像头，查看预览是否有清楚的指缝 |
| 手掌已确认：左右摆手 | 张掌已确认，还没有足够的左右摆动 | 保持张掌，左右摆动并回摆 |
| 已检测摆动：向反方向摆 | 已检测到一个方向的有效摆动 | 向反方向摆回，避免移出大框 |
| 招手已识别 | 张掌和往返摆动均满足条件 | WAVE 图案亮起；切为点赞/比心或移走手会结束招手显示 |
| 黄色框 | 找到了候选区域，尚未确认三种动作之一 | 看轮廓是否完整，并保持录入时的朝向 |
| 绿色框 + 8×8 亮图案 | 已通过类别与多帧确认 | 观察对应动作和图案是否一致 |

建议先固定摄像头，手在大框内占大约一半高度，使用均匀室内照明。不要让手与脸、肤色衣物相连；识别稳定后再逐步增加距离和背景复杂度。若比心轮廓和点赞在预览中看起来一样，本版会拒绝录入或判为未知；这是轮廓方案的能力限制，不能靠一个阈值保证解决。

## 本版实现与边界

- 手势输出只保留 1=WAVE、2=THUMB UP、3=HEART；未知不产生新图案。
- 两周期的肤色掩膜接口、原视频对齐延迟保持不变；使用掌心 32×32 区域的 Cb/Cr 平均值调整肤色窗口，兼顾较亮指尖与阴影。
- 保留 7×7 圆盘多数滤波、闭运算、连通域和目标关联。扩大操作框，允许手腕从大框底部伸出；指尖及左右贴边仍拒绝。
- 每个候选归一化到 16×16 位轮廓，三帧一致后多数合并。比较三个模板，允许上下左右一格偏移；手指区域权重更高，同时使用长宽比。距离过大或两类分数太接近时输出未知。
- 点赞、比心继续使用模板及 5/7 帧确认。张掌可由原模板，或“多根分离手指 + 掌部”的 16×16 轮廓特征确认；避免手指间距变化导致模板失配后完全无法招手。
- 张掌采用 5 帧内至少 3 帧确认，确认后容忍最多约 6 帧分类不确定。招手同时观察候选框横向位置和手指区域在手框内的横向重心，因此支持框中心基本不动的摆腕。
- 必须有足够幅度的往返运动，静止张掌、轻微抖动、单向移动不生成 WAVE。序列最长 180 个处理帧；候选连续丢失、改变目标、检测故障和退出模式会清除序列。静态轮廓仍可能受复杂背景干扰，不能保证任意姿态识别。
- 右侧保留三种 8×8 图案，新增的 16×16 黑白预览是识别输入，二者用途不同。
- 摄像头初始化、DDR、HDMI 引脚与 LVDS 物理接口未改动。其他五种主模式，以及灰度/Sobel、圆形/矩形辅助模式保留。
- 未新增完整帧缓存。准确的 XLR、RAM、DSP 和时序数据见 `reports/build_verified.json`；构建脚本会拒绝超过 60,000 XLR 或时序不通过的结果。
