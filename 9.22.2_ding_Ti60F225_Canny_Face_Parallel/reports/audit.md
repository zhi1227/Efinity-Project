# 两工程只读审计与取舍

## 文件对比

对两工程 RTL/XML/SDC 逐文件 SHA256 比较：相同 244 项，不同 24 项，Canny 工程独有 2 项，人脸工程独有 124 项。完整清单见 source_comparison.json。原主工程 392 项哈希复核未变。

## 实际原始数据通路

人脸主工程：OV5640 → Sensor_Image_XYCrop → axi4_ctrl/DDR3/异步 FIFO → lcd_data。
从这里已有两个并行分支：
1. 灰度 → 四个 3×3 窗口 → 中值 → Sobel → NMS → 双阈值 → 局部滞后 → 去孤立点 → 黑白图。
2. face_reader_720p 的 R−G 判肤色 → 7×7 低通 → 形态学 → streaming_connected_components/true_ccl → bbox_filter → bbox_overlay。
因此并行结构本来部分存在，不能再次叠加第二套完整 Canny。

独立 HLS Canny：显示流 → 近似灰度 → 5×5 Gaussian → Sobel → NMS → 双阈值 → 局部 8 邻域滞后 → HDMI。
其名为 HLS 的文件实际是手写/翻译 RTL，不是运行 PC 算法。

## Canny 比较

| 项目 | 独立 HLS RTL | 原主工程 vision | 最终选择 |

| 去噪 | 5×5 可分离高斯 | 3×3 中值 | 中值，保留原用户许可的算法路线 |
| 梯度 | 幅值饱和到 8bit；较精细方向边界 | 12bit L1 幅值，方向近似 2:1 | 12bit L1，避免饱和平台 |

## 修复与资源取舍

- 统一使用 lcd_driver 已寄存的 RGB 和对应 DE/HS/VS，避免 DDR request 的一拍相位歧义；坐标仅计一次。
- Canny 与肤色分支共享同源 RGB565、x/y、DE、帧起始；互不串行调用。
- 每个窗口用两个同步读行 RAM，只有短横向窗口寄存器。中值、Sobel、NMS、阈值、滞后各一拍。
- 原 streaming_connected_components 的 bbox 数组带异步复位及动态多路读写，倾向映射 FF/LUT；原 true_ccl 依赖行 DE 间隙，而 wrapper 冲刷两个零行时没有行间隙。过滤/叠加又各引入帧发布等待。最终移出综合清单，不把不可靠旧坐标接到新叠加。
- 复用同工作区 2026.9.21 工程的修正版 line_buffer、video_delay 和 face_grid_regions，原文件不修改。后者对 8×8 占据网格作真实八连通 BFS，非简单肤色最外框。
- BFS 网格双缓冲和队列用块 RAM；160 项 cell_sum 仍为小型逻辑表。最大 8 个框，8px 坐标量化。
- 原 camera/DDR3/PLL/TMDS/peri.xml/SDC 原样保留；未增加假时序例外。原工程非使用接口告警不等于活动通路错误。
