# Ti60F225：单人四表情、简单动作与 RISC-V 电子纸控制评估

日期：2026-09-26。仅分析，没有修改 RTL、重新构建或下载板卡。

结论：采用小型量化模型、低分辨率动作分析、轻量 RISC-V 和电子纸分块传输，有条件实现。主要约束是片上 RAM 分配、训练模型效果和接口集成。新增功能尚未综合，不能把预算当作实测结果。

用户已澄清：只有一块电子纸，提前存储四张表情图片，识别到对应表情后选图显示。按一块屏规划，不再计入两个额外设备。四种表情、图片内容/尺寸和具体动作类别尚待确认。

新增需求的推荐实现：表情分类ID→稳定性判断→RISC-V查图片地址→小缓冲读图→SPI传输→触发刷新。CPU只做选图、传输和屏幕状态管理，不需要实时绘制复杂图形。四张显示图片和识别模型权重是两类不同的数据，四张显示图不能替代表情训练数据。

## 识别方案与能力边界

- 四表情：先固定单人、正面或小角度场景。从现有候选框选择一个稳定目标，裁剪48×48灰度ROI，使用INT8小型CNN和复用MAC运算单元。目标5～10次推理/秒是设计目标，需由模型MAC量、带宽和实测决定。
- 现有红框来自肤色和几何筛选，只提供候选位置；没有眼、嘴关键点，也没有表情分类器。手、背景和光照可干扰，需要跟踪、有效性判断和低置信度/无人状态。四类别不等于模型天然很小或效果有保证。
- 简单动作：低分辨率ROI/帧差、运动质心、面积变化与时间状态机适合先实现挥手、左右移动等受控动作。点头/摇头需稳定头部跟踪；抬手需覆盖上半身，不能只用人脸ROI。暂不按全身骨架、大型时序网络或通用动作模型预算。
- 动作模块持续采样；表情模式14控制显示和推理使能。若动作和表情共用算力，要规划调度，不能因切换显示而中断动作历史。

## RISC-V 与电子纸分工

建议手写简单多周期RV32I，裸机运行，不启用Linux、MMU、大缓存或FPU。实现取指、译码、ALU、寄存器组、分支、加载/存储和内存映射外设；加入启动程序、链接脚本、程序ROM、数据RAM及指令测试。乘除可先软件实现。

CPU负责读取识别结果、滤波决策、UI绘制、SPI/GPIO、定时器和通信；卷积和视频像素处理由RTL承担。识别结果通过寄存器邮箱或异步FIFO跨时钟传递，电子纸BUSY同步后接入CPU。等待刷新不阻塞摄像头/HDMI。

作为规模参照，Efinix官方Sapphire Lite无缓存、内部存储配置在Ti60F225 C4上的表格为2761 Logic/Adders、1957 FF、24 RAM、0 DSP（Efinity 2025.2）。这些统计不是XLR，不能直接加到当前XLR；也不代表手写CPU的综合结果。当前工程工具是2025.1。

## 电子纸核对

已读取并渲染本地原理图第1页、B版手册第8/9/11页，同时核对引脚说明TXT和官方Wiki。

- 5.79inch e-Paper Module (B)：792×272，红/黑/白。B版手册典型整屏更新25秒，官方Wiki标24秒。用于稳定结果、计数或状态展示；实时动作反馈继续用HDMI。Wiki建议刷新间隔至少180秒，具体刷新策略需结合实际屏版本验证。
- 模块P1：1 VCC、2 GND、3 DIN、4 CLK、5 CS、6 DC、7 RST、8 BUSY、9 PWR。DIN/CLK/CS/DC/RST/PWR是控制器输出，BUSY是输入。BUSY高时忙，CS/RST低有效，DC低命令高数据，PWR高使能。
- 采用4线SPI，Mode0。屏内两个控制IC各负责半屏，通过寄存器区分，不能当作两个普通外接SPI从设备。需要半屏镜像和396像素宽度的字节边界处理，移植EPD_5in79b对应驱动。
- 通用模块原理图J1的1/4/5脚名称与B版裸屏手册不同。使用成品模块应连接P1；若自行制作裸屏驱动板，必须按B版手册核对FPC与升压电路。
- 模块供电/主控IO电平应匹配。2026-09-26补充核实：底板P4默认通过TXS0108E将FPGA侧1.8V转换到3.3V；所选FPGA Bank 1A/1B的Efinity约束应为1.8 V LVCMOS，不能根据User_3V3_IO名称设为3.3V。模块采用3.3V供电，VCC接P4-29，GND接P4-12/30。
- 一块屏共需DIN、CLK、CS、DC、RST、BUSY、PWR七个信号IO，另接VCC/GND。已核对底板、同目录核心板和现有约束，建议DIN/CLK/CS/DC/RST/BUSY/PWR分别使用IO14/2/4/6/16/10/22。需先重分配旧LCD端口，并处理板卡TXS0108E与模块TXB0108直接级联的兼容性问题；完整球位、原接线冲突和缓冲建议见[电子纸接线核对](电子纸接线核对.md)。此分配尚未写入工程。

缓存计算：

| 内容 | 紧凑存储 |
|---|---:|

| 一块屏黑/红两个平面 | 53856 B = 52.59 KiB |

| 四张完整红黑白图片 | 215424 B = 210.38 KiB |
| 四张128×128黑白图标 | 8192 B = 8 KiB |
| 四张128×128红黑白图标 | 16384 B = 16 KiB |

按半屏每行补齐至50字节，传输布局还可能有额外填充，不能只按紧凑像素数分配。四张完整黑白图使用普通8位BRAM约需106～108块，超过现有87块余量；四张红黑白图约需211～216块。即使改成片上ROM，通常仍消耗BRAM或逻辑资源，并不会免费获得存储空间。

优先把四张完整图存放在可访问的外部非易失存储中，为图片保留约256 KiB空间；FPGA只保留1～4 KiB传输缓冲。可以直接顺序读取Flash并发送SPI，不必先复制完整画面到片上RAM。若复用板载配置Flash，必须先确认器件容量、用户逻辑访问路径、启动位流边界和安全分区；当前工程存在旧Flash烧写相关端口，但不能据此认定已具备可用的图片读取控制器。本轮不写Flash。

若希望避免外部存储接口，可选小尺寸图标加白色背景：例如四张128×128黑白图共8 KiB，再在发送时补白。红色平面为空也按屏协议发送。此选项需额外约8块普通字节型RAM，不能忽略其对下面预算的挤占。RLE等压缩可用于简单表情图，但压缩率必须拿实际图片测量，不能预先保证。

小缓冲分次写入屏内RAM，全部发送后再触发刷新。分块传输不等于局部刷新，也不意味着刷新更快。相同识别结果不重复刷屏；结果需经过多帧稳定性判断；BUSY期间继续识别并记录最新稳定结果，不中断当前刷新或无限排队。待屏幕空闲且满足刷新间隔策略后才显示下一张图。掉电后保留的可见画面不等于屏幕能长期存储四张可切换的图片素材。

当前DDR已有四个视频帧槽，默认每槽4 MiB地址跨度，共16 MiB保留区。模型或电子纸大图可考虑DDR，但当前控制器没有自动开放的CPU端口；需要仲裁、地址划分、视频带宽保障和跨时钟处理。外接DDR容量/可用区仍需根据板卡资料确认，不能假设直接可用。

## 可执行的第一版RAM预算

以下是需要满足的设计分配目标，不是尚未存在的模块的实测消耗。

| 新增部分 | RAM预算块数 | 约束 |
|---|---:|---|
| 轻量RISC-V程序和数据 | 24 | 初始16 KiB程序＋8 KiB数据；实际固件须检查链接大小 |
| 表情ROI、权重与激活缓存 | 40 | 小型INT8模型；例如权重约16 KiB、激活复用约16 KiB，余量给ROI/行缓冲 |
| 简单动作与历史缓存 | 8 | 低分辨率/二值特征；不存720p历史帧 |
| 电子纸小缓冲与通信FIFO | 4 | 四张完整图存外部Flash，此处不含图片存储和模型权重 |
| 合计新增 | 76 | 基线169＋76＝245，剩11块 |

此预算RAM占用将达95.7%，实现余量偏小。建议先按此验证可行性，再优化已有缓存，争取至少多出十几块。DSP可先为表情MAC预留16～32块，其余逻辑/DSP在模块综合后统计。模型若超出权重/激活预算，需缩小网络、分层搬运权重或使用DDR。

只识别一个人并不自动让34块CCL RAM缩成1/8。当前VISION_FACE_MAX_FACES仍为8；改为1主要减少框列表，全图队列和网格仍在。更有收益的是ROI检测、较粗网格或重新设计单目标跟踪，但需要重新验证小脸检出与误检。

若仍需要删模式，优先评估一起删5/13：在当前高斯Canny配置下，专用灰度延迟8块、中值显示延迟5块、中值后窗口4块，存在约17块RAM的释放机会；最初灰度窗口仍供高斯Canny共享，不能删除。实际节省量以构建为准。模式10专用显示延迟仅1块，优先级较低。本轮没有删除这些模式。

## 建议实施顺序

1. 明确四种表情、四张图片的颜色/尺寸和动作列表；确认板卡扩展接口、Flash容量及访问方式。
2. 先在电脑上训练/验证四表情，测出量化权重、峰值激活和每次MAC数；同时实现轻量CPU指令验证。
3. 集成CPU、SPI、GPIO、定时器、图片读取和单块电子纸小缓冲显示，先用手动分类ID切换四图，测出真实增量资源。
4. 增加单人ROI与CNN硬件，模式14显示分类结果；接入时间滤波和低置信度状态。
5. 加入简单动作；最后全工程仿真、布局布线、存储访问压力与板上时延验证。
