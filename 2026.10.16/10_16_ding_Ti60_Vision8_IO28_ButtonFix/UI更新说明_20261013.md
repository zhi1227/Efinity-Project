# 八模式流水切换与独立 Canny 阈值页

LVDS 为1024×600、48 MHz 像素时钟。主页面采用深蓝渐变底、八张彩色图标卡片、选中描边和流水高亮条、LIVE/HOLD 标记。逐像素绘制，不增加显示帧缓存或 DDR 视频带宽。

## 模式与页面

模式顺序固定为：**1 原图、2 Canny、3 彩色红边、4 赛博边缘、5 彩边对照、6 手势识别、7 人脸识别、8 四帧对比**。模式5复用原工程的左彩色/右 Canny 对照通路；手势与四帧保存的内部控制、DDR通路、HDMI标签和界面编号一起调整。

IO28 短按切换时，高亮条带两段拖尾向下一卡片流动，约10个显示帧（178ms）抵达相邻卡片；8→1从右侧环绕回左侧。连续切换会从当前高亮位置继续移动。动画位置只在消隐区改变，整帧保持一致。

IO35 打开**独立设置页面**，不是八模式中的任意一项。页面仅显示阈值与设置操作：左右两个面板分别标注低阈值 LOW 和高阈值 HIGH，四位数字单字符格64×128像素；选中边框、LOW/HIGH/LINK 和步长实时显示。没有触摸操作。

| 按键 | 模式页面 | 阈值页面 |
| --- | --- | --- |
| IO28 | 短按切到下一模式；模式2～4长按开关彩色画中画 | 短按关闭设置并切到下一模式 |
| IO35 | 短按进入阈值设置 | 短按返回进入前的模式 |
| IO29 | 普通模式冻结/恢复；模式6录入时不冻结；模式8保存/长按清空 | 短按减少；长按冻结/恢复 |
| K1 | 模式6长按录入、短按确认手型 | 短按选 LOW/HIGH/LINK；长按改步长1/4/8 |
| K2 | 模式8选择保存的算法 | 增加所选阈值 |

打开/关闭设置保持当前算法、冻结状态与已调阈值。若需在 HDMI 观察 Canny 变化，先选模式2再按 IO35。参数限制 `1 ≤ LOW < HIGH ≤ 2040`，LINK 联动保持差值，抵达上下限时停止；参数在视频帧边界生效，LVDS也按帧更新。短按松开生效，长按约2秒。IO35长按不切页；跨页面/模式的按住再松开不触发旧功能。IO28优先于IO35，串口保留更高优先级。串口数字0～7对应模式1～8，模式命令退出设置。

### IO35 接线

| 项目 | 配置 |
| --- | --- |
| 顶层端口 | `io35_button_i` |
| 底板扩展口 | P4 / DC3-40 第 **40** 脚，`User_3V3_IO35` |
| FPGA 资源 / 球位 | `GPIOT_P_11` / **B9** |
| 接收方式 | 与 IO28 一样：**空闲低，按下高**，双级同步、约 20 ms 消抖 |
| FPGA 输入标准 | 1.8 V LVCMOS，普通输入，无内部上下拉 |

位置依据 Ti60-F225_Button_Board_V1.1_20230915 底板原理图第 7 页和 Ti60_F225_Core_V1.4 核心板管脚表。底板 P4 默认是经 TXS0108E 转换的 3.3 V 侧；FPGA 管脚为 1.8 V 侧。外接按钮应像 IO28 一样提供稳定的空闲低电平，不能悬空。

## 人数与诊断显示

仅模式7在屏幕中央显示实时人脸候选数量，其他模式显示各自说明；设置页优先显示阈值。算法保留原有肤色轮廓候选检测、源帧去重、连续确认和冻结逻辑，不新增人脸身份识别。有效空画面0、饱和8+、无效--；冻结有HOLD标记。

LVDS/HDMI模块运行状态文字与灯条已移除。摄像头/DDR内部就绪信号仍用于有效性与数据通路控制。手势指引、检测框、四帧信息保留。ROI `(40,40)～(1000,680)`、墨水屏人物和原固件不变。

```powershell
& .\tools\test_vision8.ps1 -VivadoBin 'D:\Vivado\Vivado\2019.2\bin' -Benches @('tb_vision8_controls','tb_vision8_faces','tb_vision8_frames','tb_io29_freeze_ddr')

& .\tools\test_gesture_roi.ps1 -VivadoBin 'D:\Vivado\Vivado\2019.2\bin' -Benches @('tb_roi_shared_overlay')
& .\tools\test_cpu8.ps1
# Pillow Python:
python .\tools\render_eight_modes.py
```

字库由 `tools/generate_font.py` 生成，268字符，9组512×16 ROM，两个端口保持一个时钟读延迟。新增设置标志使用640位状态包的bit123，原有CPU完整传送状态包，LVDS按帧提交；无需修改CPU/墨水屏固件。

Efinity 需要全英文构建路径，下面stage须为新的可写目录：

```powershell
$stage = 'C:\fpga_build\vision8_eight_modes'
python .\tools\stage_build.py prepare $stage
& (Join-Path $stage 'tools\build_fpga.ps1') -Efinity 'D:\Efinity'
python .\tools\stage_build.py collect $stage
python .\tools\verify_eight_modes.py
```

开始编译后不修改输入文件。收集时检查源文件哈希；生成文件、资源和建立/保持时序见 `reports/build_verified.json`，专项证据见 `reports/ui_eight_modes/validation.json`。`.bit`用于SRAM/JTAG，`.hex`用于配置Flash。仿真与编译不代替实物验证，本次未上板烧录。

`reports/io35_migration`、`reports/ui_refresh/validation.json` 与 `tools/verify_io35.py` 仅用于此前版本审计；本次改变模式编号和页面后不再适用。
