# OV5640 彩色人脸候选分析 + Canny 边缘显示

更新日期：2026-09-21（北京时间）

本目录是直接修改的工程，不是旁边的旧复现工程。目标为易灵思 Ti60F225、OV5640 DVP 摄像头、DDR3 缓冲、HDMI 1280×720 输出。Efinity 工程文件为 **Ti60_Demo.xml**，顶层为 **example_top**。

## 1. 最终画面和两条处理支路

默认显示：黑底、白色 Canny 边缘、红色人脸候选框。

```text
OV5640 → 原有采集 / DDR3 / LCD 像素时序 → 原始彩色 RGB
                                          ├→ YCbCr 肤色 → 8×8 网格 → 八连通域
                                          │             → 几何筛选 → 多框平滑/保持 ─┐
                                          └→ 灰度 → 中值 → Sobel → NMS             │
                                                     → 双阈值 → 局部迟滞 ──────────┤
原始 RGB、DE、HS、VS、坐标 → 对齐延迟 ───────────────────────────────────────────────┤
                                                                                  ↓
                                                                  显示叠加 → HDMI
```

人脸判断始终读取**原彩色图像**，不是对黑白边缘做肤色检测。Sobel 在这里负责 Canny 内部的梯度计算，并不意味着最终算法只是 Sobel。

## 2. 必须知道的算法边界

- 这是传统肤色 / 几何规则的**人脸候选区域检测**，没有训练过的人脸分类器，也不能识别身份。手臂、木色物体或暖色背景可能误检；逆光、肤色变化及脸部被遮挡可能漏检。
- 轮廓指候选区域内的 Canny 图像边缘，不是精确的人脸语义分割或人脸关键点定位。头发、衣服、背景边缘也可能保留。
- Canny 使用中值预滤波、Sobel L1 幅值、四方向非极大值抑制、双阈值以及**一次 3×3 八邻域强弱边连接**。这是流式轻量化变体，不包含整帧递归弱边追踪，不能宣称与 OpenCV 完整 Canny 完全等价。
- 中值替代高斯，主要用于抑制孤立椒盐噪声；不保证所有光照下都没有噪点。
- 八连通域在 8×8 像素网格上计算，框的原始坐标粒度为 8 像素，最多输出 8 个候选框。这是容量，不是“准确识别 8 人”的保证。
- 多框稳定器按中心距离关联，坐标按 3/4 旧值 + 1/4 新值平滑；漏检保留 3 次更新，第 4 次清除。它有跟随延迟，不提供身份跟踪，近距离交叉时可能关联错误。
- 框来源于先前完成的帧，通常落后约 1～2 帧，再叠加平滑延迟。不要把短时保留的旧框当成新检测。
- 未做板卡功耗测量，不声称已验证低功耗优势。

## 4. 怎样切换彩色画面

在 example_top.v 搜索 DISPLAY_MODE：

```verilog
localparam DISPLAY_MODE = 1;      // 1：黑白 Canny + 红框（默认）
                                  // 0：彩色原图 + 候选区域内青色边缘 + 红框
localparam CANNY_TH_LOW = 24;
localparam CANNY_TH_HIGH = 64;
```

这是**编译时选择**，改完必须重新编译并下载，不是按键开关。目前没有新增或改变板卡按键引脚。

建议第一次学习先用模式 0 确认彩色图像亮度、对焦和候选框，再改成 1 观察黑白边缘。边缘图四周约 4 像素是无效窗口边界，填黑，但 HDMI 的完整 1280×720 DE 时序保持不变。

## 5. 调参顺序

1. 先让摄像头对焦清楚，脸部亮度正常，避免背后强光；用模式 0 检查原图。
2. 如果边缘太少，先试 LOW/HIGH = 16/40；默认是 24/64。HIGH 必须大于 LOW，LOW 应大于 0。
3. 如果细碎边缘太多，试 32/80 或 40/100。不要一开始就回到 120/240，这组值在本次用户实拍反馈中明显漏掉较弱边缘。
4. 肤色阈值位于 face_candidate_pipeline.v：Cb 77～127、Cr 133～173、Y 40～235。不要为了框更多而盲目扩大范围，会增加背景误检。
5. face_grid_regions.v 默认每格至少 24/64 个肤色像素；宽高、填充率和宽高比也要同时满足。近距离脸太大、远距离脸太小会被筛掉；按实际拍摄距离调整 MIN_W/MIN_H/MAX_W/MAX_H。
6. 稳定器只能减少框闪烁，不能把错误检测变成正确检测。想进一步提升真实性，应另加人脸分类/验证算法，而不是延长保持时间伪装稳定。

## 6. 打开、编译、下载

1. 打开 Efinity 2025.1，选择本目录的 Ti60_Demo.xml，不要打开同名旧目录。
2. 检查目标芯片为 Ti60F225。已有摄像头、DDR3、HDMI 引脚和 PLL 配置保留，不要改成其他板卡的约束。
3. 完整执行 Synthesis、Interface、Place and Route、Generate Bitstream；不要跳过失败步骤。
4. 查看 outflow/Ti60_Demo.timing.rpt，关注 clk_pixel 的 Setup/Hold 余量及其他时钟。bit 存在不代表时序通过。
5. 打开 Programmer，选择已安装驱动的 Single RS232-HS 下载器，模式选 **JTAG**，文件选 outflow/Ti60_Demo.bit。
6. 点击开始，看到 finished with JTAG programming 后观察 HDMI 实际画面。

JTAG 写入易失 SRAM，重新断电后会丢失本次配置。**本轮没有擦写启动 Flash**。不要选择 Active / JTAG Bridge 去覆盖 Flash。不要给键盘、鼠标或其他 USB 设备替换驱动。

也可以在本目录 PowerShell 手动编译：

```powershell
& 'C:/Efinity/2025.1/bin/efx_run.bat' Ti60_Demo --prj --flow compile
```

下载器 URL 会随连接变化；手动命令操作前先运行官方 ftdi_pgm.bat --list_usb，不能盲目复制其他设备 URL。
