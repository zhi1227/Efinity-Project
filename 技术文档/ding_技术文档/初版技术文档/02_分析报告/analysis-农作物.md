## 2. 逐章内容摘要

### 摘要（无标题样式）
目的：一页给出痛点—方案—四大优势—实施方式—价值。结构为「问题（人工依赖、效率低、成本高）→ 平台（ZYNQ）→ 四大创新（异构加速/端边协同/多源融合/模块化）→ 数据流（OV5640 + 环境传感器 → PL 处理 → PS 诊断 → 双屏输出）→ 价值」。关键词 4 个。可复用点：**摘要采用「痛点→平台→N 个创新点→实施→价值」五段式**，可直接作为模板。

### 第 1 章 项目概述
- 1.1 选题背景与意义：背景三段（国家战略→现有方案局限→市场缺口），意义三条（突破边缘算力、实现自主智能、提升诊断维度）。
- 1.2 项目目标：功能目标 4 条（列表式）、**性能指标表0（8 项可量化指标）**、学习目标 4 条（分号式长句，用 `Normal (Web)` 样式）。
- 1.3 技术规格：表1（目标器件 ZYNQ-7000 / 开发环境 Vivado + Vitis classic 2024.2 / 语言 Verilog、C / 验证平台三驱小车 / 应用领域）。
- 论证方式：**目标即指标**——功能目标用文字，性能目标立刻落到 8 行数字表（精度 >90%、30 fps、1 px/2 clk、PL <50 W、PS <10 W、病斑 <2 cm²、延迟 <39 ms、蓝牙 >50 m）。这是全文需求可追溯性的起点。

### 第 2 章 需求分析与系统设计
- 2.1「选题背景与意义」（标题错误，实为需求分析）：功能需求 4 组（多源采集 / 图像处理与诊断 / 平台控制与交互 / 扩展与接口），每条以「必须在 PL 端…」「必须在 PS 端…」的强约束句式写明**责任端**；性能需求直接复用表2。
- 2.2 系统架构设计：顶层架构（图2-1 + 一段文字列 8 个组成部分）；状态机设计（图2-2 + **4 状态说明 + 4 条状态转移条件**，条件写成布尔表达式 `camera_init_done & ddr3_init_done & dvi_pll_locked`）；时序设计（时钟源与分配 → 三时钟域 → 关键复位信号 → 时序要点与保证：跨时钟域/帧一致性/输出像素时序/上电顺序）。
- 2.3 接口设计：模块功能概述（fifo2mig_axi：写 FIFO→DDR3→读 FIFO 桥接，AXI_LEN=8'd31 即 32 拍）；输入接口规格（时钟复位、写方向、AXI 从属侧）；输出接口规格（按 **AW / W / B / AR / R 五通道**逐条写「数据位宽 / 时序关系 / 状态指示」，含 `awaddr += (awlen+1)<<4` 的地址步进公式）。
- 论证方式：**需求（功能/性能）→ 架构（框图）→ 控制（状态机）→ 时间（时钟域）→ 边界（接口）**逐层收窄，每层都能回溯到第 1 章的指标。

### 第 3 章 详细设计与实现
- 3.1 核心算法设计：一段总述（core_code 在 pclk_bufg_o 逐像素完成色彩转换→去噪→边缘→形态学，流水线目标 1 px/2 clk，服务 30 fps 与延迟指标），随后 **4 个 H3 各配一张处理效果图**，无文字说明——算法原理、定点化、硬件映射全部缺失。
- 3.2 关键模块设计：[ddr3_ctrl_2port 模块] → 功能描述（4 条：跨时钟与宽度转换、突发事务与地址管理、仲裁与背压控制、上电初始化/就绪 + 设计目标一句）→ 端口定义（带参数 `WR_DDR_ADDR_BEGIN/END`、`RD_DDR_ADDR_BEGIN/END` 的完整 Verilog 端口声明，按「时钟/复位、写端 FIFO、读端 FIFO、DDR3 物理」四组注释分区）。
- 3.3 逻辑设计：顶层结构与时钟域（物理/MIG 域、写端域、读端域三域并列）→ 写路径（16→128 bit 打包、32 拍固定突发 512 B、地址回绕、阈值触发）→ 读路径（对称拆包、`m_axi_rready = ~rd_fifo_alfull` 背压）→ 仲裁与事务管理（轮询+阈值、五通道握手、BRESP/RRESP 兜底）→ 地址与帧区间 → 复位/就绪与帧同步（上电顺序、`wrfifo_clr/rdfifo_clr` 与 VSYNC/frame_begin 对齐防撕裂）。
- 3.4 资源使用设计：LUT 策略（移位替代乘法、倒数 LUT、比较器共享、滑窗复用、SRL 做短延迟）→ 寄存器使用（逐级流水、控制跨域两级同步、握手寄存、高扇出拆分）+ 时钟资源（BUFG/BUFGCE 门控、禁止逻辑劈时钟、三域异步组）→ 存储资源规划（BRAM：行缓冲/异步 FIFO/帧缓冲；LUTRAM：小 LUT/掩膜行缓存），末尾一句总结「大容量可复用→BRAM，小容量查表→LUTRAM/SRL」。
- 论证方式：**模块级「功能→端口→内部数据通路→资源代价」四段式**，且资源设计明确服务于前面给出的吞吐/时延指标（自顶向下的约束继承）。

### 第 4 章 LLM 辅助设计优化记录（最长）

## 4. 写作方法论提炼

### 4.1 需求 → 可测规格
- **功能需求与性能需求分离**：功能需求写成「谁负责 + 必须做什么」（“必须在 PL 端通过硬件流水线…”“必须在 PS 端融合…”），性能需求全部落成 `指标名 | 技术参数` 的两列表。
- **指标必备要素**：可量化的物理量 + 明确的不等号方向 + 单位。全文 8 项指标即 8 个验收点，后续所有设计与结果都围绕它们展开。
- **同一张需求表被复用于三处**（1.2 指标表、2.1 性能需求表、8.2 达成度表）。优点是追溯方便，缺点是造成内容重复（表0 与表2 完全一致）；规范做法是「定义一次，后续用交叉引用」。
- **技术规格表**（表1）固定五要素：目标器件 / 开发环境（含版本号）/ 编程语言 / 验证平台 / 应用领域——可直接复制为通用模板。

### 4.2 模块文档化五件套
从 3.2 + 3.3 可提炼出模块章节的标准骨架：
1. **功能描述**：一句话定位（“基于 Xilinx MIG 的双端口帧缓冲控制模块”），再列 3–4 条「内部完成什么」（跨时钟与宽度转换 / 突发与地址管理 / 仲裁与背压 / 上电就绪），并以「设计目标：解耦 X/Y/Z 三个时钟域，保证 720p@30fps 连续帧流」收尾。
2. **端口定义**：给完整可编译的 `module ... #(parameter ...) (...)`，并按「时钟/复位、写端、读端、物理接口」注释分区；参数要说明物理含义（`WR_DDR_ADDR_END = 1280*720*4` 字节地址）。
3. **内部结构/时钟域**：列出每个时钟域的名字、来源、职责，并声明域间只用「异步 FIFO + 宽度转换」。
4. **数据通路**：写路径与读路径成对描述，每步写清位宽变化（16-bit → 128-bit → DDR3）与触发条件（`wrfifo_wren=1`）。
5. **资源代价**：LUT/寄存器/BRAM/LUTRAM 各自的使用策略与理由（移位替代乘法省 DSP、滑窗行缓冲复用、小表用 LUTRAM），最后一句总结取舍准则。
补充：**状态机写法** = 状态图 + 逐状态说明（状态名 + 该状态做什么 + 硬件动作）+ 转移条件表（写成布尔表达式）+ AIX 类协议的「通道 × 位宽/时序/状态指示」三列表。

### 4.3 算法文档化四步
第 3.1 与 4.3 合并后可提炼为：
1. **原理**：算子用途与在流水线中的位置（color transform → smooth → edge → morph → overlay）。
2. **定点化**：位宽与数值范围（H 0..360 用 9 bit、S/V 0..255 用 8 bit）、精度取舍（Q12 倒数、`>>12` 还原、饱和度 `>255 ? 255`）。
3. **硬件映射**：把数学式翻译成硬件友好形式——`60*x = (x<<6)-(x<<2)`（去 DSP）、`num * recip(den) >> 12`（去除法器）、`mult60()` 函数封装、`generate` 二选一宏（`USE_RECIP_LUT`）。
4. **资源/时序代价**：给出「面积（recip LUT 仅 3 Kb 级）、时序（延迟 4 拍 → 3 拍）、功耗（CE=de 门控）」三类量化收益，并说明如何用 `LAT` 参数自动对齐 vs/hs/de 控制信号。
> 原始文档在此处有明显缺口：3.1 的四个算子只有图、没有文字，定点化与硬件映射全部散落在第 4 章的对话里。**规范做法是把 4.x 中的结论回填到 3.1**。

### 4.4 结果文档化三类报表
1. **资源报告**：应为「资源类型 | 可用 | 已用 | 占比 | 对比基线」表；本文档只有截图（表 3 的前身缺位），是可改进点。
2. **时序报告**：表3 的列设计非常值得复用——**`时序指标 | 目标值 | 实际值 | 裕量`**，逐时钟列出，正裕量用 `+x MHz` 表示，一眼看出收敛程度。
3. **对比/回归表**：表4 的列设计——**`指标 | 目标值 | 实际上板测试后的实际值`**，并**如实保留未达标项**（89%、43 m、59 W）。诚实披露 + 在 7.1 把未达标项转成改进条目，构成完整的「结果→反思→计划」链条。
4. 优化结果的表达范式（来自 4.2/4.3）：**现象（WNS=-0.37 ns，5.37 ns vs 5.00 ns）→ 根因（组合锥过深、扇出过大）→ 措施（编号列出 6 条）→ 结果（WNS=+0.28 ns，Fmax≈205–208 MHz）→ 闭环说明（关键路径已移出地址加法/比较锥）**。

### 4.5 论证与语言风格
- 普遍使用「目标 → 做法 → 接口/产出 → 验收 → 里程碑」五段式（第 7 章最标准）。
- 大量使用「量化对照」而非形容词：`<39 ms`、`>90%`、`1 px/2 clk`、`512 B/突发`、`+0.28 ns`、`2.4 W`。

- 待改进处：结论与价值章节偏口号化（如「看不见的细节，才是产品级系统的底气」），缺少数据；第 6 章创新点纯声明无佐证；标题式冒号（“功能描述：”“逻辑设计：”“存储资源规划:”）与中英文标点混用。
