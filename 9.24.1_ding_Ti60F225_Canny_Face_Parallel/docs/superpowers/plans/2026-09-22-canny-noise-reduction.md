> 目标：降低边缘图噪点，同时**不损失**边缘细节。

## 2. 实测现状（已核实，实现时直接引用）

### 2.1 Canny 链真实结构（逐模块读过源码）

```
lcd_data(RGB565)
  → rgb565_to_gray          (点运算)
  → [LB#1 DW8] → median3x3  (3×3 排序网络，替代高斯)
  → [LB#2 DW8] → sobel3x3   (Gx+Gy 共用一窗，零乘法器，输出 mag[11:0] + dir[1:0])
  → [LB#3 DW14] → nms3x3    (沿梯度方向比较)
  → canny_threshold          (160/80 双阈值，2bit 分类 cls)
  → [LB#4 DW2] → hysteresis_local
  → edge_despeckle(thresh_i=2)
  → edge → RGB888 → 显示
```

### 2.2 关键常量与端口（**改任何一级都必须同步这一项**）

- `example_top.v:1367` `localparam CANNY_LATENCY = 19;`（16 流水 + 3 去噪）
  → 用于 `de_sr/vs_sr/hs_sr` 移位链对齐 `lcd_de/vs/hs`。
  **新增任何一级流水，必须把这个数加上该级延迟，否则显示错位。**
- `canny_threshold` 阈值：`example_top.v` 里
  `localparam CANNY_TH_HIGH = 12'd160; CANNY_TH_LOW = 12'd80;`
  （`USE_PORTS=1`，改这两个数即可，模块不用动）
- `edge_despeckle.thresh_i`：当前 **`4'd2`（最弱档）**，端口可调，注释标明「2=弱 3=中 4=强」
- `mag` 满量程 **0..2040**（=|Gx|+|Gy|，满对比边缘约 1020）

## 3. 技术结论：两个问题的直接回答

### 3.1 「中值 + 高斯」串联 —— **不推荐**

两者的**机理不同、目标相反**：

| | 中值 3×3 | 高斯 3×3 |
|---|---|---|
| 针对噪声 | **脉冲 / 椒盐** | 高斯型（传感器噪声） |
| 对边缘 | **保边**（排序，不做加权平均） | **必然模糊**（加权平均，这正是它的目的） |
| 对高斯噪声 | **几乎无效** | 有效 |

串联的三个问题：

1. **中值对高斯噪声无效** → 若你的噪声是高斯型，「中值+高斯」里中值那份成本白付。
2. **高斯的模糊会抵消中值的保边收益** → 你先用中值保住了边，再用高斯把它模糊掉，净效果是
   「拿到高斯的边缘定位损失 + 两份硬件成本」。
3. 成本翻倍：多 1 个 `line_buffer_3x3`（1280×行的 RAM）+ 约 1.5k LUT。

**正确做法是二选一**：
- 噪声**脉冲型** → 只留 `median3x3`（要更强可换 3×3 → 5×5 中值，但 5×5 中值 LUT 约 3~4 倍，不划算）
- 噪声**高斯型** → 把 `median3x3` **换成** 3×3 二项式 `(1,2,1)×(1,2,1)` 可分离高斯
  （成本 ≈ 1 个行缓存 + 少量加法，且可用 `{v,1'b0}` 拼接实现乘 2，零乘法器）

> ⚠️ 注意：**前置平滑对「去短线段」帮助有限**。短线段是**几何/连通性**问题，
> 不是像素统计问题 —— 平滑只能让它变暗，不能让它消失。所以要靠后处理（§4）。

### 3.2 「Canny 之后加腐蚀 / 开运算」—— **方向对，但直接做会毁掉边缘图**

★ **核心事实：Canny 经 NMS 后边缘只有 1 像素宽。**

3×3 全 1 结构元做腐蚀时，一条 1 px 竖线的中心像素，**左右邻居都是 0** → 被腐蚀掉；
整条线逐像素消失，**后续膨胀也救不回来**。
所以 **erosion→dilation（开运算）作用在原始边缘图上 = 大面积消失**，
现象是「更黑」而不是「更干净」——正是你刚遇到的症状方向。

正确的操作选择：

| 你想做的事 | 该用什么 | 不该用什么 |
|---|---|---|
| 去孤立点 | **邻域计数**（`edge_despeckle` 已在做） | 腐蚀 |
| 补断线、连缺口 | **闭运算**（dilate→erode） | 开运算 |
| 去 2~5px 短线段 | **行程长度 / 连通域过滤** | 形态学开运算 |
| 去细碎毛边 | 提 `TH_LOW`，或二项式高斯替换中值 | 中值+高斯串联 |

另外，项目里的 `morph_erode3x3_stream` 是做**人脸二值块**的
（3×3 全 1 腐蚀 / 竖直 N×1 开运算）：
- 竖直 N×1 开运算会把**所有水平边**抹掉 → 不能搬到 Canny 链
- 3×3 全 1 腐蚀同 §3.2 的问题 → 直接抹掉 1px 线

**结论：不要给 Canny 链加形态学开运算。** 已有的 `edge_despeckle` 用的正是
「邻居数 + 对向邻居对」判据，是**为 1px 细线定制**的去噪方式，比形态学开运算正确得多。

## 4. 方案（按性价比排序）

### P0 —— 零新增硬件，先榨干现有旋钮（**建议先做，当天可验**）

| 旋钮 | 位置 | 建议扫描范围 |
|---|---|---|
| `edge_despeckle.thresh_i` | `example_top.v:1355` | `2 → 3 → 4`（现在是最弱的 2） |
| `CANNY_TH_LOW` | `example_top.v` 第 5 节 localparam | `80 → 100 → 120`（弱边是噪点主要来源） |
| `CANNY_TH_HIGH` | 同上 | `160` 保持；若边缘断裂再降到 `140` |

**同时判定噪点类型**（决定后面动不动前置滤波）：

| 现象 | 判定 | 对策 |
|---|---|---|
| 孤立白点逐帧闪动 | 脉冲噪声 | 中值已有 + 加强 `thresh_i`；**不要加高斯** |
| 2~5 px 短线段 | 几何问题 | 走 P1（长度过滤） |
| 成片细碎毛边、边缘抖动 | 梯度噪声 | 提 `TH_LOW`；或走 P2（换二项式高斯） |

判定方法：录一段**静止场景**的原始录像（不要动相机），逐帧看同一位置是否稳定。
用现成的 `_analysis/extract_any.ps1` 抽帧即可。
（注：`_analysis/frames5/` 里已有的抽帧是**用手机拍屏幕**，对 1px 线有混叠，
不能用来判定碎片是真实的还是拍摄造成的 —— 必须看原始录像。）

### P1 —— 新增「水平行程长度过滤」级（**性价比最高的一级**）

**做法**：某像素被保留，当且仅当以它为中心的 `2N+1` 水平窗口内边缘像素数 ≥ K。
- 效果：长度 < K 的短线段被清除；长边几乎不受影响 → 精确对应 R1+R2
- 实现：**只需一个 `2N+1` 位移位寄存器 + 一个 popcount**，
  **不需要行缓存**（纯水平），延迟 +N 拍
- 成本估算：N=8 → 17bit 窗口，popcount(17) 约 4~5 级 LUT ≈ **30~50 LUT，0 RAM**
- 建议参数：`N=8, K=4`（可先用参数扫描）

**注意**：新增一级 → `CANNY_LATENCY` 必须 `+N`；且 `edge_despeckle` 已有
「对向邻居」判据，本级的判据要与它**互补而非重复**（它是局部 3×3，本级是 1D 长程）。

### P2 —— 行程长度过滤升级为 2D（若要更强的去短线）

在 P1 基础上加**竖直方向**支持度（需要 1 个 `line_buffer_3x3`, `DWIDTH=1`）：
- 行方向行程 + 上下行匹配 → 真正区分「短噪块」与「细长边」
- 成本：+1 行缓存（RAM） + 少量 LUT，延迟 +2 拍（行缓存）
- 建议在 P1 实测不够时再做

### P3 —— 若确认是高斯噪声，替换前置滤波（**换，不叠**）

把 `median3x3` 换成 3×3 二项式 `(1,2,1)×(1,2,1)` 可分离高斯：
- 优点：对高斯噪声有效，且比 5×5 中值便宜；可分离 → 2 个 1D 卷积
- 成本：≈ 1 个 `line_buffer_3x3` + 加法器；**建议用 `parameter` 二选一（中值/高斯）**，
  避免误留两套
- ★ 不要「中值 + 高斯」串联（§3.1）

## 7. Review Focus（最容易忽略、必须有测试兜住的点）

1. **`CANNY_LATENCY` 忘了加** —— 现象是整屏错位/撕裂，但很容易误判成「噪点」。
   每加一级，先改这个数再上板。
2. **`edge_despeckle` 的 `keep` 不依赖中心像素** ——
   `keep = (ncnt > thresh_i) | ((ncnt == thresh_i) & opp)` 里没有 `& win[4]`。
   副作用：中心为 0 但周围有 ≥3 个边缘像素时会**被置 1**（等效补洞/膨胀）。
   本意可能是补断线，但与「去噪」目标方向相反。**P0 调 `thresh_i` 时要意识到这一点**：
   `thresh_i` 调高会同时削弱补洞能力。若发现噪点里有「被新造出来的」像素，从这个点查。
3. **行首/行尾的窗口跨界** —— 1D 行程过滤在行边界会看到上一行的数据，
   必须在 `de` 上升沿/帧起始清窗口，否则每行首尾各出现一条伪边缘。
4. **照片混叠 ≠ 真实碎片** —— 判定噪点必须用原始录像，不要依据手机拍屏幕的抽帧。
5. **不要给 Canny 输出加形态学开运算**（§3.2）—— 这条如果搞错，会得到「全黑」，
   而且会误以为是阈值问题，浪费一整轮排查。
