# Ti60F225：Project1 八模式图像处理与三类规则手势

这是 `FPGA-Edge-Detection-Project1` 的独立 Ti60 移植工程。目标为 Ti60F225/C4、OV5640 和 HDMI。原 Quartus 工程和 9.27 的工程均未覆盖。

工程入口为 `Ti60_Demo.xml`，顶层为 `example_top.v`。板级部分取自 `2026.9.27/Ti60_Sobel_Gesture_Demo`；本工程使用 `src/project1/ep1_video.v`，不实例化该旧工程的模板手势算法。复制保留的其他旧算法文件不在当前构建源清单中。原项目 RTL 参考副本位于 `reference/original_rtl`。

## 板上操作

- JTAG 下载后自动进入 **M3 SOBEL 黑底白边**，初始阈值 100；无需按键即可查看。
- **M0～M7 是屏幕模式编号，不是按键编号。K3／RESET 是硬件复位，不能作为模式切换键。** 本地核心板 V1.4 原理图确认：K1→N2/CSI、K2→M2/CSO、K3→J5/CRESET_N。
- **K1（N2）短按：**下一模式；**长按约 0.8 秒：**上一模式。模式 0～7 循环。
- **K2（M2）短按：**边缘阈值加 5；**长按约 0.8 秒：**减 5。范围 0～255，初值 100。
- 每次长按只触发一次，松开不会再次触发；开机已按住的键须先松开。
- 从默认 M3 开始，K1 短按依次到 M4、M5、M6、M7、M0、M1、M2、M3；K1 长按反向切换。
- 设置在下一帧生效；阈值不会因换模式而重置。按键不是画面冻结键。

| 模式 | 图像处理 |
|---|---|
| M0 ORIGIN | 原始彩色图像 |
| M1 GRAY | 灰度 |
| M2 MEDIAN | 3×3 中值 |
| M3 SOBEL | 中值后 Sobel 二值边缘 |
| M4 PREWITT | 中值后 Prewitt 二值边缘 |
| M5 EROSION | Sobel 二值边缘进行 3×3 腐蚀 |
| M6 DILATION | 上一级结果进行 3×3 膨胀 |
| M7 GESTURE | 肤色筛选后的灰度→中值→Sobel→腐蚀→膨胀，叠加红框和原三类规则输出 |

二值像素是黑底白色前景。细线在腐蚀后消失属于该运算本身的效果，M5/M6 不保证比 M3 的边缘更多。窗口边界填黑，不裁掉 HDMI 有效像素。输出仍为 1280×720；沿用板级约 74.4 MHz 像素时钟、1650×750 总时序（约 60.1 Hz）。

顶部 `M` 是模式；`T` 是十进制边缘阈值；`G` 是分类标签；`F` 是十进制特征值。`G:NONE` 表示无有效目标或落入规则间隙。屏幕显示替代原数码管；UART TX 保持空闲，本工程未增加串口协议。

## 手势规则的实际含义

采用原 `recognize.v` 的标签和严格比较：F>300 为 `PALM`（全掌），220<F<280 为 `FIST`（拳头），F<200 为 `FINGER`（一指）；其余值为 `NONE`。无有效目标始终为 `NONE`，不会因为 F=0 而误报一指。

**F 不是指头数，也不是真实周长面积比。** 原 `Gesture_Posion.v` 累计的是扫描过程中四个包围盒极值被更新的次数；本移植保留该口径：

`F = floor(((xmax-xmin)*(ymax-ymin)) / extrema_update_count)`

这套原始规则明显受目标大小、距离、背景和分辨率影响，并非训练好的通用手势模型。真实全掌/拳头/一指是否可分，必须看板上实测；不能从红框出现或仿真规则通过推断识别准确率。请固定镜头、均匀照明，让单手在简单背景中以近似距离和位置展示三种姿势，记录 F 与 G。初始分类门限保留原值，位于 `src/project1/ep1_gesture.v` 的 `ep1_classify` 中；K2 调节的是前面的边缘阈值，不是这三个分类门限。

红框和 G/F 来自最近完成的一帧，当前画面仍持续实时输出。退出 M7、更改阈值、无目标时会清除过期结果。统计在完整帧边界结算，除法使用 24 拍迭代实现并保护零分母。

## 本次修复和适配

- 替换 Cyclone IV 的 PLL、SDRAM、VGA 和 Altera 行缓存/字模 IP 接口，接入已有 Ti60 摄像头、DDR3 与 HDMI 链路。
- 灰度系数为 77/150/29；M7 保留原 Cb(77,127)、Cr(133,173) 开区间肤色条件，修正色度与亮度的像素错拍。
- 精确 3×3 中值，Sobel/Prewitt 使用 21 位平方和比较阈值平方，数学上等价于原整数平方根判定，不改为 L1 近似。
- 腐蚀/膨胀使用全部九个邻域像素，修复原代码将 p31 写成 p21 的问题。
- 参数化行宽，所有图像分支与 RGB/DE/HS/VS/坐标对齐；接通原未连接的手势特征与分类输出；修复复位、帧间混用和无效目标。
- 控制口继续使用 Ti60 的 K1/N2、K2/M2，1.8 V LVCMOS；没有使用原 Cyclone IV 的引脚表。

## 复现

在本工程目录的 PowerShell 中执行：

```powershell
# Python 3 标准库即可；只生成离线仿真向量，不参与 FPGA 运行。
python tools/reference.py
./tools/test_rtl.ps1

# Efinity 2025.1 全流程，检查所有 setup/hold 关系；不下载。
./tools/build_ti60.ps1

# 仅在本机板卡已连接时，通过 JTAG 配置 SRAM；不写 Flash。
./tools/program_sram.ps1
```

`tools/prepare_project.py` 是初始建工程脚本，会从 9.27 基础工程重新生成源清单，正常复现不需要运行它。生成位流为 `outflow/Ti60_Demo.bit`；工具可能同时生成 `.hex/.bit.bin`，本交付下载脚本只使用 JTAG SRAM。

K3／RESET 会触发硬件重新配置；由于本次只下载 SRAM，按硬复位后可能重新载入 Flash 中的旧程序。此时需再次运行 `program_sram.ps1`，不能把硬复位后的旧画面当成本版本。

仿真、时序、下载与实机状态见 `reports/DELIVERY.md`。只能将有证据的项目标记通过。
