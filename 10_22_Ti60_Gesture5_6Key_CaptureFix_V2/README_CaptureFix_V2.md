## 本次实际改动

1. `rtl/vision8_ddr.v`：空格跳过逻辑增加 `!end_aux`。原版在一帧最后一行之后仍可能递增行号、回绕并重新读取旧图；定向测试在规定的 1536 个 32 位字之后又读出额外数据。修复版停止在帧末，不重复发起读请求。
2. 新 `rtl/vision8_aux_fifo.v`：AUX 从“128 位回包拆成四个写周期”改为整 128 位接收，像素侧再按 32 位读取。容量仍为 4KiB，四个同步读 RAM bank；读侧每消费完一组才推进跨域 Gray 指针，避免把一次跳四个字的多位变化当作安全 Gray CDC。
3. `rtl/vision8_ddr.v`：删除原逐拍拆包状态，PiP 的四个 32 位取样先合成一个 128 位组；保留原字节、像素和半字顺序。按现有预留容量发起突发，测试中已预留的 AUX 突发无需四拍停顿。MAIN 与摄像头路径、快照写 FIFO 保持原接口。
4. `rtl/vision8_frames.v`：增加四帧底部诊断文字，使用既有 ASCII 字库。锁存首次抓拍错误的阶段/源帧号，以及首次 AUX 不足的坐标/源帧号。编译参数 `DIAGNOSTICS=0` 可关闭底部诊断；不会关闭本轮数据通路修复。
5. `example_top.v`：增加一个 160 位握手式诊断快照 CDC，传 DDR 侧计数和状态；AUX 读水位来自像素时钟域。原 640 位菜单字段和五手势状态未被覆盖。
6. `Ti60_Demo.xml`：把新 FIFO 加入真实综合源码清单。`Ti60_Demo.peri.xml` 和 `Ti60_Demo.pt.sdc` 保持备份字节内容。

这两项数据通路改动有 RTL 依据和测试支持，但尚不能断言它们解释了原照片中的全部现象。若本版仍出现灰图，应读取下方诊断字段继续定位，不能删除健康判断或用更长超时掩盖错误。

## 按钮和模式

模式仍为：1 原图 → 2 Canny → 3 红边 → 4 赛博 → 5 彩边对照 → **6 四帧** → 7 手势 → 8 人脸候选。

- 四帧中 IO29 **短按保存一张**，不是普通模式的冻结开关；忙时不能重复保存。
- IO34 短按选 RAW/Canny/红边/赛博，IO29 再保存。先用 RAW 验证。
- 四次填满，第五次替换最早一格，其他格不变。
- IO29 长按约两秒：清空四格、算法回 RAW，留在四帧。
- IO28 短按：清空四格、退出到手势，释放抓拍专用冻结。后台事务必须安全排空；重入后为空。
- 其他模式的 IO29 冻结/恢复、IO34/35 阈值、K1 画中画、K2 Canny 联合/HIGH/LOW 选择按原六键版保留。

常用操作速查（本轮没有更改）：

| 所处画面 | 操作 |
|---|---|
| 任意模式 | IO28短按到下一模式；从四帧退出会先清空 |
| 模式2～4 | K1短按开关画中画 |
| 模式2、5的Canny | K2短按依次选择联合、仅HIGH、仅LOW；进入时为联合，默认LOW=40/HIGH=80 |
| 边缘模式2～5 | IO34短按减、IO35短按加；IO34长按切步长1/4/8；IO35长按恢复当前算法默认参数 |
| Canny联合调节 | LOW变化一个基础步长，HIGH变化两个基础步长；默认加一次为41/82 |
| 模式7手势 | IO34长按约两秒进入录入，短按确认；IO28退出并取消未完成步骤 |

长按后松开不补发短按。上电先松开全部按键，避免启动按住保护使第一次操作被忽略。

保存的是 1280×720 全视野按偶数行列取样得到的 640×360 RGB565 图像，不是左上角裁剪，也不是任意比例无级缩放。一张 460800 字节，四格加临时替换槽共五槽，每槽地址间隔 0x80000，从 DDR 0x01000000 开始。

## 四帧底部诊断怎么看

全部数字为十六进制。底部左侧必须能看到 **V2.22**，用于识别本版。

| 字段 | 含义 |
|---|---|
| S | 无 E 错误时为当前抓拍状态；E 非零时为首次失败所在阶段 |
| E | 首次抓拍错误码，下一次抓拍或清空/退出后清除 |
| A | 首次 AUX 显示不足：1=未 ready，2=FIFO 空；下一次抓拍或清空/退出后清除 |
| U | 显示欠载累计次数；表示曾发生，不等同当前仍失败 |
| L | 四个二进制位依次为用户冻结请求、合成冻结请求、抓拍锁、DDR 冻结应答 |
| P | 四个二进制位依次为 source_ok、processing_ok、AUX ready、AUX empty |
| N | 当前抓拍的缩小像素计数，720p 成功采样应为 0x38400（230400） |
| F | E 非零时为抓拍首次失败的源号；否则 A 非零时为 AUX 首次失败时的主视频源号；无错误时为实时源帧号。各格标题 F 才是该图保存时的源号，结合 XY 定位具体图片 |
| C | 已接受的抓拍请求数；控制层忙时忽略的按键不计入 |
| W | 快照写入累计字节数，完成一张为 0x70800（460800） |
| M | 主读 DDR 完整返回帧次数；是否完整消费还需结合 P 中的 processing_ok |
| X | DDR 返回协议错误累计数 |
| Q/m | 当前 AUX 可读 32 位字水位 / 此次抓拍以来记录的最小水位 |
| XY | 第一次 AUX 显示不足发生的屏幕坐标 |
| D | DDR 首次错误码，保持到系统复位，不通过清空目录伪造恢复 |

S：0 空闲；1 等冻结；2 等稳定完整源帧；3 释放快照 FIFO 复位；4 等采样帧；5 采样；6 等 DMA 完成；7 取消排空；8 复位收尾。

E：01 冻结等待超时；02 完整帧等待超时；03 采样时源号变化；04 坐标错误；05 采样被新帧打断；06 快照 FIFO 满；07 DMA 失败或采样完整性失败；08 其他阶段超时；09 采样时健康/处理完整性失效。

D：11 BRESP；12 RRESP；13 RID；14 RLAST/数量；15 读事务长期无进展；16 快照 DMA 看门狗。永久没有 RLAST 或 B 响应时只报告故障，不强行撤回事务或重置整个 DDR。

健康状态举例：空格未读图时 P=D 可以是正常的“源好、处理好、AUX 未就绪且空”；正在读图时 P=E 表示源好、处理好、AUX 已就绪且非空。U/A 只有在需要图像的区域遇到不足时才记录。抓拍期间 L 常为 7，完成并解除冻结后应回到 0。

## 上板验证顺序

1. 保持按钮释放，使用本工程新 `outflow/Ti60_Demo.bit`。Programmer 选 **JTAG**，做 SRAM 临时下载；SPI Active 要用 hex。不要把 bit 改后缀冒充 hex。
2. 确认原图实时变化，再按 IO28 进入第6模式。检查底部 V2.22。
3. 先 RAW，IO29 短按一次后松开，等忙结束；应出现真实缩略图，而不只是 RAW 标签。拍下底部 S/E/A/U/L/P/N/W/D。
4. 移动摄像头前的物体，已有图片应保持；换算法再保存，直到四格；第五张只替换最早格。
5. 保存期间按 IO28：应清空退出；手势/原图能看到新动作，冻结应答应解除。重入四帧为空，能再次保存。
6. 若仍灰图，先不要连续按键：记录 E/A、XY、P、W、U、D 和所处阶段。若标签有但 A=1/2，优先检查显示回读；若 W 未达 0x70800，优先检查采样/写入。保留新 bit 哈希及照片。

本版未执行上板下载或 Flash 烧写。确认实板后再决定是否烧入 Flash，SRAM 下载断电即丢失。
